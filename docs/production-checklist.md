# NoteGen 公共测试实例上线清单

这份清单适用于官方公共测试实例，也可作为自行部署的生产前检查。项目免费且不提供商业 SLA，但仍需要满足最低安全、恢复和滥用控制要求。

## 1. 首次安装

- [ ] 使用空数据库启动，确认 Web 自动进入安装向导。
- [ ] 设置清晰的实例名称并创建唯一的首位管理员。
- [ ] 管理员使用独立强密码登录，并启用 TOTP。
- [ ] 完成安装后重新访问 `/v1/installation/status`，确认安装入口已经关闭。
- [ ] 默认注册策略设置为“仅邀请”或“关闭”。

## 2. 域名与网络

- [ ] 为后台准备独立二级域名，例如 `sync.notegen.top`。
- [ ] `PUBLIC_BASE_URL` 与用户实际访问的 HTTPS origin 完全一致，不包含路径。
- [ ] HTTPS 证书链完整，并设置自动续期。
- [ ] 反向代理支持 WebSocket Upgrade、大附件请求体和 Range 下载。
- [ ] 外网无法绕过反向代理直接访问服务端口。
- [ ] 仅在代理网络可信时启用 `TRUST_PROXY=true`。

## 3. 密钥与权限

- [ ] `AUTH_SECRET` 使用至少 32 字节的随机值，保存在秘密管理或受限环境文件中。
- [ ] PostgreSQL、S3 和 SMTP 使用独立最小权限凭据。
- [ ] `.env`、数据库密码、SMTP 密码和备份密钥没有进入版本控制、日志或截图。
- [ ] 至少保留一种管理员恢复路径，并确认不会重新开放普通注册。

## 4. 容量与滥用控制

- [ ] 配置合理的单对象、单附件和请求体大小上限。
- [ ] 确认登录、注册、设备授权和上传接口具有限流。
- [ ] 为数据库、Blob 存储和备份介质设置容量告警。
- [ ] 明确异常账号停用、邀请撤销和明显滥用数据的处理方式。
- [ ] 公开注册仅用于短时测试；没有持续维护能力时保持“仅邀请”。

## 5. 备份与恢复

- [ ] PostgreSQL 与 Blob 数据在同一恢复点配套备份。
- [ ] 备份副本与运行实例分离，访问权限独立。
- [ ] 完成至少一次隔离环境恢复，确认账号、实例 ID、附件和同步数据一致。
- [ ] 记录最近成功备份、最近恢复演练时间和负责人。
- [ ] 向用户明确公共测试实例不是唯一备份，NoteGen 本地数据必须保留。

## 6. 邮件

- [ ] 不需要邮件时保持 SMTP 关闭；登录、设备授权和手动邀请仍应正常工作。
- [ ] 启用 SMTP 时配置正确的发件地址、TLS 和连接超时。
- [ ] 发送测试邮件，确认队列、重试和脱敏日志符合预期。
- [ ] 邮件不可用不会阻断同步服务的健康状态。

## 7. 监控与验收

- [ ] `/health/live` 与 `/health/ready` 由外部监控定期检查。
- [ ] 需要 Prometheus 时启用 `/metrics`，并限制到受信网络或配置 Bearer Token。
- [ ] 日志和磁盘容量具备告警；日志不包含 token、密码或同步密文载荷。
- [ ] 临时启用公开注册并执行 `pnpm test:self`，成功后恢复原注册策略。
- [ ] 使用两台真实 NoteGen 设备验证登录、设备关联、同步、断线恢复和设备撤销。

## 8. 对外说明

- [ ] 登录页可以访问 `/service/` 服务说明。
- [ ] 用户知道服务免费、不提供商业 SLA，并可能因维护或资源限制调整。
- [ ] 用户知道默认托管密钥模式和高级端到端加密模式的差异。
- [ ] 提供账号停用和数据删除入口，并在官网或服务说明中给出维护者认可的反馈渠道。

## 尚需部署者独立完成

仓库无法代替部署者完成真实域名解析、证书签发、生产密钥生成、服务器防火墙、异地备份介质、恢复演练和监控告警接收。这些项目全部确认后，公共测试实例才适合对外开放。
